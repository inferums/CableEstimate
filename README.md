# CableEstimate

Расчёт ведомости объёмов работ (ВОР) для высоковольтных кабельных линий 0,4–220 кВ.
По участкам трассы и способам прокладки считает земляные работы, конструкции,
кабельные работы и благоустройство и выгружает ведомость в Excel по форме
проектной документации. Трасса вводится вручную или импортируется из файла
съёмки; план и продольный профиль выгружаются в DXF.

## Запуск

```bash
npm install
npm run dev      # http://127.0.0.1:3000
```

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер разработки |
| `npm run build` | сборка в `dist/` |
| `npm test` | тесты расчёта (vitest) |
| `npm run lint` | ESLint |
| `npm run typecheck` | проверка типов |
| `npm run check` | типы, линтер и тесты разом — запускать перед коммитом |

## Правила расчёта

Эти правила закреплены тестами; менять их — значит менять тесты осознанно.

- **Баланс грунта сходится.** Весь разработанный грунт равен сумме основания,
  верхней засыпки, объёма конструкций и обратной засыпки.
- **Проработан только класс 110–220 кВ.** На 0,4–10 и 35 кВ траншеи другие, и
  кабель укладывается не в лотках, а расчёт пока ведётся по конструкциям
  110–220 кВ. Поэтому эти классы помечены «в разработке» и выбрать их нельзя;
  проект, уже сохранённый на таком классе, открывается с предупреждением.
  Снимать пометку (`inDevelopment` в `VOLTAGE_META`) следует вместе с
  правилами расчёта для этих классов, а не раньше.
- **На 110–220 кВ каждая цепь идёт в своей конструкции** — своём лотке,
  трубном блоке, скважине ГНБ. На 0,4–10 и 35 кВ цепи идут в общей.
- **На 35 кВ лотков нет.** Участок с лотками на 35 кВ в ведомость не попадает
  и отмечается ошибкой.
- **Характеристики лотков и плит — из серии 3.006.1-2.87**, а не из геометрии:
  объём бетона и масса берутся из номенклатуры.
- **Ведомость делится на четыре фиксированных раздела**: земляные работы;
  каналы, трубы и конструкции; кабельные работы; благоустройство. Способ
  прокладки — подраздел внутри раздела. Нумерация позиций сквозная.
- **Концевые муфты считаются на линию**, а не на участок.

## Выполнение и сверка со сметой

Работы сдаются частями: сначала переход ГНБ, потом траншея с прокладкой одной
строительной длины. Акт закрывает выбранные участки — у каждого можно закрыть
часть длины в метрах — в выбранных разделах ведомости. Объёмы считаются по
закрываемой части и правятся под факт.

**Сохранённый акт заморожен.** Он не пересчитывается при правке проекта, иначе
принятые работы терялись бы при каждом изменении трассы. Позиция, исчезнувшая
из ведомости после принятия, остаётся в накопительной ведомости с пометкой
«нет в проекте».

Смета импортируется из выгрузки локальных смет в Excel. Единицы в ней идут с
множителем («1000 м3»), он учитывается при сверке. Наименования расценок и
позиций ведомости не совпадают, поэтому связь задаёт пользователь; автоподбор
по схожести только предлагает вариант и не занимает одну позицию сметы дважды.

## Импорт съёмки

Координаты геодезические: **X — север, Y — восток**. Длина участка —
расстояние между пикетами по координатам; положение пикета — центр его точек.
Плюсовка в имени пикета — метры: `ПК12+5` — это 12 пикет и 5 м.
Формат `.xls` не поддерживается — файл нужно пересохранить в `.xlsx`.

## Объекты и хранение

Приложение ведёт несколько объектов сразу; переключатель — в шапке слева.
Объекты лежат в **IndexedDB** браузера: каждый отдельной записью
`project:<id>`, список — записью `index`. Список производен от записей и
восстанавливается по ним, если разошёлся. Если IndexedDB недоступна
(приватное окно, запрет хранения), приложение переходит на `localStorage` и
говорит об этом в списке объектов: там лимит около 5 МБ на весь сайт, а
проект со сметой занимает порядка 300 КБ.

Сохранение автоматическое, через 0,4 с после правки. **Отказ записи виден** —
в шапке вместо «сохранено» появляется «не сохранено»: молчаливый отказ
означал бы, что работа уходит в никуда.

Проект, сохранённый прежней версией приложения в единственном ключе
`cableestimate:project`, при первом запуске становится первым объектом
реестра; старый ключ при этом не удаляется.

Копия объекта (кнопка «копия») переносит параметры и трассу, но **не акты и
не смету**: принятые объёмы относятся к своему объекту. Открытие `.json`
создаёт новый объект, а не затирает текущий.

## Облако (Vercel Blob)

Облако переносит объекты между машинами и хранит копию на случай поломки
компьютера. Обмен запускает человек кнопкой «Облако» в шапке: файловое
хранилище не умеет сливать правки, и молчаливая двусторонняя синхронизация
рано или поздно затёрла бы чью-то работу.

Раскладка файлов в хранилище:

```
objects/<id>/meta.json          сведения для списка: название, шифр, время, машина
objects/<id>/project.json       проект целиком
objects/<id>/acts/<actId>.json  каждый акт отдельным файлом
```

**Акт пишется один раз и не переписывается.** Акт заморожен с момента
подписания, поэтому совпадение идентификаторов — это один и тот же акт, а не
две версии. Даже перезапись `project.json` с другой машины не может потерять
принятые объёмы: при получении акты из отдельных файлов объединяются с
местными.

Расхождение версий приложение не разрешает само: если в облаке версия свежее
той, с которой сводились, отправка отвечает конфликтом, и человек решает,
перезаписывать ли.

### Правка серверной функции

**В `api/*.ts` нельзя импортировать значения из `src`** — и вообще из соседних
файлов. Функции на Vercel не собираются в один файл: каждый `.ts`
компилируется сам по себе, и импорт разваливает функцию на старте
(`ERR_MODULE_NOT_FOUND`, наружу — пустой 500 без объяснений). Импорты типов
при компиляции исчезают и потому безопасны.

Поэтому правила раскладки файлов и кодирования пароля описаны дважды: в
`api/sync.ts` и в `lib/cloud-shared.ts` для браузера. Что копии не разошлись,
следит `lib/api-contract.test.ts` — он же проверяет, что в функции не завёлся
импорт значений извне.

`/api/health` отвечает без пароля и без единого импорта: если он работает, а
`/api/sync` падает — дело в зависимостях функции, а не в механизме.

### Настройка

1. Создать **приватное** хранилище Blob: Storage → Create Database → Blob →
   access **Private**, и подключить его к проекту. Публичное не годится —
   в объектах данные заказчиков.
2. Задать переменную окружения `CABLE_SYNC_PASSWORD` (Settings → Environment
   Variables). Пока она не задана, `/api/sync` отвечает «не настроено»:
   функция иначе открыта всему интернету, приватность хранилища её не
   закрывает.
3. Тариф: Hobby у Vercel — для личного некоммерческого использования; рабочий
   инструмент требует Pro.

Пароль один на всех, кто пользуется приложением, и хранится в браузере. Если
понадобится разграничение по людям — кто что закрыл, — одного пароля станет
мало, и это повод переходить на учётные записи и базу данных.

## Формат проекта

Объект выгружается в `.json` с номером версии формата. При открытии проект
старой версии переводится на текущую (`lib/migrate.ts`); всё, что пришлось
изменить, показывается пользователю. При изменении модели или справочника
поднимайте `SCHEMA_VERSION` и дописывайте миграцию.

Данные лежат в браузере конкретного компьютера. Перенести объект на другую
машину можно через облако или через `.json`; `.json` остаётся и способом
оставить копию перед опасной правкой.
